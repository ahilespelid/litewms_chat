Чат для любого сайта: диалоги, голосовые и файлы, непрочитанное, присутствие и push. Один и тот же API
использует веб-клиент (`/embed`, `/app`) и будущее мобильное приложение.

## Как подключить сайт

1. Администратор чата создаёт приложение: `php artisan chat:app "ЛК litewms" --origin=https://test.litewms.ru`.
   В ответе три значения: публичный `app key`, `secret` (подпись токенов входа) и `server token` (серверный API).
   `secret` и `server token` хранятся **только на бэкенде** сайта.
2. Бэкенд сайта для уже вошедшего у себя пользователя выдаёт **handoff-токен** — JWT HS256, подписанный `secret`:

| claim | значение |
|---|---|
| `iss` | публичный `app key` |
| `sub` | id пользователя на вашем сайте |
| `exp` | не позже чем через 10 минут от `iat` |
| `jti` | уникальная строка: токен принимается один раз |
| `name`, `email`, `avatar`, `role` | профиль (необязательно); `role` — подпись вроде «Продавец» |
| `operator` | `true` — человек видит все диалоги поддержки приложения |

3. Страница отдаёт токен чату: встроенный `embed.js` сам запрашивает его у вашего эндпоинта (`token-url`), а мобильное
   приложение передаёт его в `POST /auth/exchange` и получает рабочий Bearer-токен.

```php
// PHP (Laravel): эндпоинт сайта, который вызывает embed.js
$now = time();
return response()->json(['token' => \Firebase\JWT\JWT::encode([
    'iss' => config('chat.app_key'), 'sub' => (string) $user->id, 'iat' => $now, 'exp' => $now + 120,
    'jti' => (string) \Illuminate\Support\Str::uuid(), 'name' => $user->name, 'role' => 'Продавец',
], config('chat.app_secret'), 'HS256')]);
```

## Диалоги и контекст

Диалог бывает `support` (обращение к операторам), `direct` (двое) и `group`. К диалогу можно привязать **контекст** —
сущность вашего сайта (`context.type` + `context.id`, например `request` / `123`): так кнопка «Чат» в карточке заявки
открывает именно переписку по этой заявке. Кто с кем может общаться, определяет бэкенд сайта через серверный API.

## Гости

Вход без аккаунта (`POST /auth/guest`) по умолчанию **выключен**: приложение отвечает `403 «Гостевой режим выключен.»`, а форма «Написать нам» на `/app` не показывается. Включается флагом `--guests` при создании приложения или командой `chat:setting guests on` для существующего. Обращение гостя попадает в диалог поддержки ко всем операторам приложения (`operator: true` в токене входа или команда `chat:operator`); если операторов ещё нет, сообщение хранится в БД, а новый оператор автоматически входит во все открытые диалоги поддержки (накопленное при этом считается прочитанным).

## Удаление диалога

`DELETE /conversations/{id}` — «удалить для себя»: диалог скрывается только у вас, новое сообщение вернёт его, но без прежней истории. `DELETE /conversations/{id}?scope=all` — «удалить навсегда»: диалог пропадает у всех. Разрешено оператору (диалог поддержки) и создателю (личный диалог, группа), в диалоге это поле `can_delete_for_all`. Сообщения и контекст при этом остаются в базе как архив (мягкое удаление), но недоступны ни в интерфейсе, ни через API; новое обращение по той же заявке открывает пустой диалог.

## Закрепление, пересылка и «Поделиться»

`PATCH /conversations/{id}` с `pinned: true|false` закрепляет диалог вверху вашего списка (не больше 5, у каждого свои закрепления).
`POST /conversations/{id}/messages/{message}/forward` с `conversation_ids` пересылает сообщение в ваши диалоги: копия приходит от вашего имени с полем `forwarded_from` (автор оригинала), файл и голосовое копируются, пересланное редактировать нельзя.
`PUT /conversations/{id}/messages/{message}/share` делает ссылку на своё сообщение (`GET` — настройки, `DELETE` — отключить): `access` = `members` (участники диалога), `app` (любой вошедший в чат) или `anyone` (все по ссылке), `expires_in` в секундах и необязательный `password`. Открывает ссылку `POST /shared/{token}` без токена (для `anyone`) или с Bearer-токеном; ошибки приходят с полем `code`.

## Реальное время

WebSocket-сервер совместим с протоколом Pusher (Laravel Reverb). Авторизация каналов: `POST /api/v1/broadcasting/auth`
с тем же Bearer-токеном. Достаточно одного приватного канала `private-participant.{id}` — по нему приходят события:

| событие | когда |
|---|---|
| `message.created`, `message.updated` | новое / изменённое / удалённое сообщение, в payload — сообщение и диалог с вашим `unread_count` |
| `message.read` | собеседник прочитал диалог (`last_read_message_id`) |
| `conversation.updated` | появился новый диалог или изменился счётчик на другом вашем устройстве |
| `conversation.removed` | вас убрали из диалога |

Presence-канал `presence-conversation.{id}` показывает, кто сейчас в открытом диалоге, и доставляет событие `typing`.

## Ошибки

`401` — нет/просрочен токен; `403` — нет прав; `404` — диалога нет **или он вам недоступен**; `422` — ошибка в данных
(тело: `message`, `errors`); `429` — слишком часто.
